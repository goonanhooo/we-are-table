# we are table. — PC·폰 함께하기

[현재 구현·검증·실행 상태](../../STATUS.md)

각자 최신 Windows 또는 macOS Unity 실행본으로 같은 Steam/Unity 방에 들어가 게임 장면을 봅니다. 한 테이블의 네 다리를 PC 키보드와 웹 폰으로 섞어 조작할 수 있습니다. 호스트 PC가 물리를 계산하고 다른 Unity PC에 동기화합니다. Unity 실행본 없이 보는 사람은 웹 관전 화면을 열 수 있습니다.

## UI 미리보기 (게임 없이 폰 화면 고치기)

컨트롤러 화면(`public/index.html`, `style.css`, `controller.mjs`)을 고칠 때는 Unity 실행본이나 방 코드 없이 **미리보기 페이지**로 확인합니다. 진짜 컨트롤러 페이지에 가짜 게임 연결(`public/preview-mock.mjs`)을 붙여 여러 폰 크기를 한 화면에 띄웁니다.

- **배포본에서 바로 보기**: <https://we-are-table-controller.eraser-room-game.workers.dev/preview> (마지막으로 배포한 파일 기준)
- **고치면서 보기(다른 컴퓨터 포함)**: 이 폴더에서 아래 명령을 실행하고 <http://localhost:4190/preview>를 엽니다. Node.js만 있으면 되고 `npm install`도 필요 없습니다. 파일을 저장하면 화면이 자동으로 다시 불러와집니다.

```sh
npm run preview
```

- 위쪽 버튼으로 능력(기본·기린·테니스공·눈사람·우주오징어), 조작 방식(기본·자이로·조이스틱), 눈사람 얼음/풀림, 내 다리, 다른 사람이 맡은 다리, 게임 연결 여부, 화면 크기(100·75·50%)를 바꿉니다. 각 폰 화면 아래에 누른 버튼이 표시됩니다.
- 폰 하나만 크게 보려면 `/index.html?preview&mode=giraffe&leg=1&busy=0010&unity=1&ice=frozen`처럼 주소로 상태를 지정합니다(`ctl=gyro|stick`은 조작 방식, `screen=entry`는 입장 화면). 같은 와이파이의 폰에서는 `http://<이 컴퓨터 IP>:4190/index.html?preview`로 엽니다.
- `?preview`가 없으면 `preview-mock.mjs`는 아무 일도 하지 않습니다. 실제 서비스 동작은 그대로입니다.
- 미리보기는 화면 확인용입니다. 게임과의 실제 연결은 `node --test tests/*.test.mjs`와 아래 Cloudflare 실제 배포 검사로 확인합니다.

## 플레이

1. 최신 실행본에서 **함께하기 → 방 만들기**를 누릅니다. 게임이 Cloudflare 방을 자동으로 생성하고 고정 중계 서버에 직접 연결합니다. 로컬 Node 서버나 터널을 켤 필요가 없습니다.
2. 다른 Unity PC는 **함께하기 → 친구 방에 참가**에서 호스트의 PC 방 코드를 입력하거나 Steam 친구 방을 선택합니다. Steam이 있으면 Steam 방, 그렇지 않으면 Unity Relay 방을 사용합니다.
3. 호스트의 Unity 로비에서 **폰 QR**을 눌러 공통 QR 하나와 8자리 폰 입장 코드를 확인합니다. 모든 폰이 같은 QR을 스캔합니다. [고정 컨트롤러](https://we-are-table-controller.eraser-room-game.workers.dev/)에서 코드를 직접 입력해도 됩니다. PC 방 코드와 폰 코드는 별개입니다.
4. 폰은 서로 다른 빈 다리에 배정됩니다. 큰 네 색 버튼으로 빈 다리를 바꿀 수 있고, PC가 선택한 다리는 가져갈 수 없습니다. PC에서 폰이 쓰는 다리를 중복 선택할 수도 없습니다.
5. 호스트가 맵·난이도를 정해 시작합니다. 호스트 PC가 능력을 2·3·4·5로 선택하고, 폰은 선택된 능력의 신축·접착·얼음·분출 동작을 담당합니다.
6. 실행본 없이 게임 화면만 보려면 같은 고정 주소의 `/watch`에서 관전 코드를 입력합니다. 관전 코드는 폰 입장 코드와 별개이며, 방 생성 응답과 브리지의 `WatchCode`에 전달됩니다. 클라우드 관전 코드 복사 UI는 아직 없습니다. 영상은 최대 960px·초당 8장이며 오디오는 보내지 않습니다.

`시작하기`는 기존 싱글 게임입니다. 폰 화면에는 조작기만 표시됩니다. 다른 Unity PC의 화면은 웹 영상 복사가 아니라 기존 게임 네트워크가 동기화한 장면입니다.

아이폰에서는 QR의 **HTTPS 주소를 Safari에서 직접 열고** **자이로 켜기**를 누른 뒤 동작/방향 접근을 허용합니다. 방향 센서와 동작 센서 권한을 한 번의 버튼 입력으로 요청합니다. 폰을 곧게 세우고 **수직 보정**을 누르면 조작을 시작합니다. 테이블 위의 큰 반투명 방향 원과 점이 기울기를 보여 주며 선택한 다리의 색을 따라갑니다. 방향 원은 진한 4px 테두리, 반투명 채움과 큰 중앙 점으로 표시합니다. 센서 입력 횟수, 각도 숫자와 능력 선택 버튼은 표시하지 않습니다. 신호나 권한에 문제가 있을 때만 짧은 안내가 나옵니다. **터치**를 누르면 방향 버튼으로 돌아갑니다. 능력에 맞춰 하단 버튼의 이름과 개수가 바뀝니다. 기본 모드에서는 능력 버튼을 숨깁니다.

| 현재 능력 | 폰 동작 버튼 |
|---|---|
| 기린 | 다리 늘이기 / 다리 줄이기 |
| 테니스공 | 테니스공 접착 / 접착 해제 |
| 눈사람 | 얼음 / 풀기 |
| 우주오징어 | 가로 전체 너비의 분출 버튼 하나 |

눈사람의 얼음·풀기는 눈사람 선택을 유지하면서 테이블 전체의 얼음 재질·마찰 상태만 바꿉니다. 호스트의 4번은 눈사람 선택을 켜고 끄며, 다른 능력을 고르면 눈사람 선택도 해제됩니다. 여러 폰이 동시에 얼음과 풀기를 누르면 풀기를 우선합니다. 능력을 바꿀 때 누르고 있던 동작 입력을 해제하고, 이전 능력에서 늦게 도착한 입력도 중계에서 차단합니다.

PC 게임 화면에서는 ESC 옵션의 다리 색 표시가 선과 방향 표시를 함께 켜고 끕니다. 폰이 네 다리를 모두 맡아도 호스트의 복도 튜토리얼이 진행됩니다. 각 다리의 네 방향 버튼을 누르거나 자이로로 네 방향을 기울여 연습하고, 버튼을 놓거나 폰을 중립으로 되돌리면 다음 다리로 넘어갑니다. 자이로 기울기에도 게임 화면의 방향 화살표가 표시됩니다.

◉로 테이블의 색 표시를 끄고 켤 수 있으며, 다리를 바꾸는 색 버튼은 계속 남습니다. 기본 테이블 그림은 `Table.prefab`의 상판·다리 크기와 BL 노랑·BR 파랑·FL 초록·FR 빨강 위치를 바탕으로 만든 SVG입니다. 게임의 색 엑스레이처럼 네 다리의 윤곽이 상판을 통과해 보입니다. `node tools/render-table.mjs`로 다시 생성할 수 있습니다. 기린·테니스·얼음·오징어가 게임에서 활성화되면 해당 모드의 기존 Unity 렌더 이미지로 바뀝니다.

세로 320×568px과 390×844px에서 큰 색 버튼, 자이로 버튼, 방향 버튼과 ＋/−가 스크롤 없이 한 화면에 들어오는 것을 브라우저에서 확인했습니다. 실제 아이폰 센서 검증과 별개로 센서 권한·보정·기울기·회전 신호는 자동 검사로 확인합니다.

원본 다리 물리는 수직축 회전과 한 축 기울기의 두 관절로 구성되어 있습니다. 폰을 세운 상태에서 비틀면 수직축 회전이 동작합니다. 기울어진 상태에서는 해당 관절이 기울기 방향을 정하는 데 쓰입니다. 다리 자체의 길이축을 독립적으로 비트는 세 번째 관절은 현재 원본 구조에 없어 구현되지 않았습니다.

## 구성과 실행

기본 서비스는 [Cloudflare 고정 서버](https://we-are-table-controller.eraser-room-game.workers.dev/)입니다. Worker가 컨트롤러 파일을 제공하고, SQLite 기반 Durable Object가 게임별 WebSocket 방을 분리합니다. 호스트 키는 생성한 게임 메모리와 해당 방에만 보관하며 빌드나 폰 URL에 넣지 않습니다. 방 코드는 7일 후 만료되며, 게임 실행 후 새 호스트 세션에서 새 방을 생성합니다.

`Assets/Resources/PhoneControllerService.json`에는 공개 서버 주소만 있습니다. 호스트가 함께하기를 시작하면 `PhoneControllerBridge`가 HTTPS로 방을 만들고 WSS로 직접 연결합니다. `unity/` 파일을 다른 프로젝트로 옮길 때 `PhoneControllerService.json`은 `Assets/Resources/`에 넣으세요.

Cloudflare 계정에 다시 배포하려면 이 폴더에서 다음 명령을 실행합니다. 기존 Worker 이름과 Durable Object 마이그레이션을 유지하세요. 서버 배포 중에는 연결이 잠시 끊어질 수 있고 게임과 폰이 다시 연결합니다.

```sh
npm install
npx wrangler@4.51.0 deploy
```

이전 로컬 중계도 유지합니다. `PhoneController.json` 또는 `--phone-config=...`가 있으면 해당 설정을 우선 사용합니다. 로컬 방은 Node.js 22 이상으로 `node server.mjs`, 임시 터널은 `node internet.mjs` 또는 Windows의 `start.ps1`로 실행합니다. 이 경로에서만 `cloudflared`가 필요하며, 터널을 재시작하면 주소가 바뀝니다. 원래 `lone-atlanta-tables-posing.trycloudflare.com`은 원래 컴퓨터의 이전 버전으로 남아 있고 새 배포와 연결되지 않습니다.

macOS 빌드 메뉴는 Steam 플러그인을 포함한 앱에 테스트용 임시 서명을 적용하고 전체 서명을 검증합니다. 정식 배포용 Developer ID 서명·Apple 공증은 별도 절차입니다.

Windows 빌드 메뉴는 64비트 Mono 실행본을 생성합니다. `WAT_WINDOWS_OUTPUT`으로 EXE 출력 경로를 지정할 수 있으며, 같은 폴더의 `build-summary.json`에 결과·오류·경고 수를 기록합니다. 배포할 때는 EXE만 보내지 말고 `_Data`, `MonoBleedingEdge`, UnityPlayer·Steam DLL을 포함한 전체 폴더를 ZIP으로 전달하세요. 2026-10-16 최신 Windows 빌드와 파일 검사는 통과했으며 실제 Windows 실행 검사는 아직 하지 않았습니다.

호스트 키가 들어 있는 `.runtime/PhoneController.json`은 다른 PC에 보내거나 Git에 넣지 마세요. 일반 게임 배포본은 공개 서버 주소만 포함합니다.

## 검사

첫 명령은 로컬 자동 검사이며, 두 번째는 별도로 로컬 중계와 임시 터널을 켠 경우의 인터넷 검사입니다.

```powershell
node --test tests/*.test.mjs
node tests/internet.mjs
```

로컬 테스트는 폰과 PC 다리 예약의 상호 배제, 공통 코드로 네 폰 입장, 빈 다리로 전환, 관전자 인증 및 화면 전달, 입력과 자이로 회전 신호, 연결 해제와 재접속, 폰의 능력 전환 차단을 검사합니다. 실제 서로 다른 장소의 Unity PC 여러 대와 폰을 동시에 사용한 플레이 검사는 별도로 필요합니다.

### Cloudflare 실제 배포 검사

```sh
WAT_CONTROLLER_ORIGIN=https://we-are-table-controller.eraser-room-game.workers.dev node cloudflare/test-remote.mjs
```

2026-10-16 공개 HTTPS/WSS 검사 10개가 통과했습니다. 두 방 격리, 공통 QR로 네 폰 배정, PC 예약, 능력별 입력 마스크, 자이로 포즈, 입력 만료, 관전 프레임 전달, 잘못된 코드와 호스트 재접속을 포함합니다.

또한 별도 Mac QA 게임이 로컬 서버 없이 방을 자동 생성한 뒤 Cloudflare를 통해 실제 관절 이동·기린 신축·테니스 접착/해제·얼음/풀기·오징어 분출과 연결 해제 등 9개 검사를 통과했습니다. 브라우저의 얼음·풀기 버튼으로 실제 Mac 상태가 바뀌는 것도 확인했습니다. 390×844 화면은 스크롤 없이 표시됩니다. 이는 자동 폰 클라이언트와 합성 포즈 검사이며, 실제 아이폰 센서와 여러 장소의 Steam PC 동시 플레이 검사를 대체하지 않습니다.
